# Find the Lattice (Lattice) — Cryptohack

**Category:** NTRU-like Encryption / LLL on [1, h; 0, q]  
**Difficulty:** Medium

---

## Challenge Overview

This challenge implements an **NTRU-like** encryption scheme. The public key is `h = g * f⁻¹ mod q` where `f, g` are small polynomials (here: integers). Encryption:
```
e = r·h + m  (mod q)
```
with small `r`. Decryption uses the private key `f`:
```
a = f·e mod q = f·(r·h + m) = r·g + f·m  (mod q)
m = (a * f⁻¹) mod g
```

We are given:
- `q` (large prime ~512 bits)
- `h` (public key)
- `e` (ciphertext)

The private key `(f, g)` is small: `f, g ≈ √q`. The lattice
```
L = [ 1  h ]
    [ 0  q ]
```
contains the short vector `(f, g)` (or `(g, f)` depending on convention). **LLL reduction** recovers it.

---

## Vulnerability

**Small private key** → LLL on 2D lattice.

The matrix
```
M = [ 1  h ]
    [ 0  q ]
```
has determinant `q`. The vector `v = (f, g)` satisfies `v·M = (f, f·h + g·q) ≡ (f, g) (mod q)`? Wait.

Actually, in NTRU:
- `h ≡ g·f⁻¹ (mod q)` ⇒ `f·h ≡ g (mod q)`
- So `(f, g) ≡ (f, f·h) (mod q)` = `f·(1, h)`

The lattice generated by rows of `M` contains all vectors `(x, x·h + y·q)`. The vector `(f, g)` is in the lattice if `g = f·h + k·q` for some `k`. But `g = f·h mod q`, so `g = f·h - k·q` for some `k`. Thus `(f, g) = (f, f·h - k·q) = f·(1, h) - k·(0, q) ∈ L`.

The vector `(f, g)` has norm `√(f² + g²) ≈ √(2q)` (since `f, g ≈ √q`). The lattice determinant is `q`. By Gaussian heuristic, the shortest vector has length `≈ √(2/πe) * √q ≈ 0.48√q`. Since `||(f,g)|| ≈ 1.4√q`, it's not the absolute shortest, but it's still **unusually short** and LLL will find it.

In practice, running `M.LLL()` in SageMath gives a reduced basis where the first row is `(±f, ±g)` (or `(±g, ±f)`).

---

## Attack Flow

1. Construct matrix `M = [[1, h], [0, q]]` over `ZZ`
2. Run LLL: `M_LLL = M.LLL()`
3. First row `(f, g)` or `(g, f)` (up to sign) = private key
4. Decrypt: `a = (f * e) % q`, `m = (a * inverse_mod(f, g)) % g`
5. Convert `m` to bytes

```python
# Lattice basis
M = Matrix(ZZ, [[1, h], [0, q]])

# LLL reduction
M_LLL = M.LLL()

# First row = (f, g) or (g, f) up to sign
f = abs(M_LLL[0, 0])
g = abs(M_LLL[0, 1])

print(f"f = {f}")
print(f"g = {g}")

# Decrypt
def decrypt(q, h, f, g, e):
    a = (f * e) % q
    m = (a * inverse(f, g)) % g
    return m

secret = decrypt(q, h, f, g, e)
print(long_to_bytes(secret))
```

## Why LLL Works Here

| Parameter | Value | Significance |
|-----------|-------|--------------|
| `q` | ~512 bits | Lattice determinant |
| `f, g` | ~256 bits | `||(f,g)|| ≈ √(2q)` |
| Gaussian heuristic | `≈ 0.48√q` | Expected shortest vector |
| `||(f,g)|| / √q` | `≈ 1.41` | Within LLL's approximation factor |

LLL finds a basis where the first vector has length `≤ 2^((n-1)/4) * det(L)^(1/n)`. For `n=2`: `≤ √2 * √q ≈ 1.41√q`. Our target `(f,g)` has length `≈ 1.41√q` — **right at the boundary**. In practice, SageMath's LLL consistently recovers it.

---

## Connection to NTRU

This is a **scalar (non-polynomial) variant of NTRU**:
- Original NTRU: `f, g ∈ Z[x]/(xⁿ-1)`, convolution product
- This challenge: `f, g ∈ Z`, ordinary multiplication mod `q`
- Lattice dimension: `2` (vs `2n` for polynomial NTRU)

The attack generalizes: for polynomial NTRU, construct the `2n × 2n` NTRU lattice and run LLL/BKZ.
